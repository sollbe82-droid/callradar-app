# 콜레이더 — 유저 아이디어 → 뼈대 흡수 절차
*작성 2026-07-21 · "차후 유저가 모여 아이디어가 나올 때 이 뼈대에 잘 녹는가"에 대한 답과 도구*

> 결론 먼저: **그렇게 되도록 뼈대를 지었다.** 대부분의 유저 아이디어는 "본체 안 건드리고 한 줄/값 하나"로 흡수된다.
> 이 문서는 그걸 **매번 확인하는 절차**다. (설계헌장 원칙 1·5의 실행 도구)

---

## 1. 흡수 판별 — 5문항 (아이디어 오면 이걸로 분류)
새 아이디어가 오면 순서대로 묻는다. **하나에 걸리면 그 방식으로 흡수:**

1. **화면에 뭔가 보여주기?** → 화면 등록소에 **카드 한 줄**(surface·size·help). *예: "심야할증 따로 보고 싶다"*
2. **새 입력방식/데이터?** → 멀티소스에 **source 한 줄**(기여로 흡수). *예: "카드영수증도 찍어서 넣고 싶다"*
3. **회사·유형별로 규칙이 다름?** → `driver_settings` **값** 또는 `driver_type` **플래그**. *예: "우리 회사는 사납금 계산이 달라"*
4. **새 수입/지출 항목이나 계산?** → income/expense **entry type** + (필요시) **토글**. *예: "세차비도 경비로", "명절 보너스 수입"*
5. **읽어주거나 물어보는 것?** → AI **lens**(읽기) 또는 **ai source**(쓰기·확인형). *예: "이번 주 수락률 어때?"*

→ **5개 중 하나로 떨어지면 = 무한확장 성공(본체 불변).**
→ **어디에도 안 떨어지면 = 새 뼈대 후보**(6번으로).

---

## 2. 아이디어 파이프라인 (유저가 모였을 때)
```
수집(카페·앱 내 제보·핫존) 
   → 분류(§1 5문항) 
   → 뼈대 매핑(카드/소스/값/항목/AI) 
   → 설계헌장 7원칙 통과 
   → 등록소 한 줄 or 값 하나로 반영
```
- **집단지성도 뼈대로:** "콜 제보 사진 → 핫존"처럼 유저 데이터가 기능이 되는 것도 source/집계로 흡수(AI 설계와 연결).
- **속도조절:** 사용자는 확장을 기쁨으로 받음. 단 헌장 원칙 5(덜어내는 용기)로 "지금/나중"을 같이 정함.

---

## 3. 새 뼈대가 필요한 순간 (경고 신호)
아래가 보이면 **멈추고 뼈대 재검토**(억지로 우겨넣지 말 것):
- 5문항 **어디에도 안 맞는다.**
- 카드 **규격을 4번째로 늘려야** 한다(3규격으로 못 버팀).
- 소스/항목을 **억지로 늘리거나** 특수 로직을 화면에 박아야 한다.
- 한 아이디어가 **여러 뼈대를 동시에 크게** 바꾼다.
→ 이땐 새 근본 뼈대(과거 예: 멀티소스, driver_type)로 승격 검토. **신중히, 규격 남발 금지.**

## 4. 워크드 예시 (진짜 녹는지 증명)
| 유저 아이디어 | 흡수 경로 | 본체 변경 |
|------|------|------|
| "심야할증 따로 보고 싶다" | ①카드 + ④계산 항목 | 등록소 한 줄 |
| "카드영수증도 찍어 넣고 싶다" | ②소스(ocr) 한 줄 | 없음 |
| "세차비 경비 분류 추가" | ④expense entry type | 등록소/항목 한 줄 |
| "우리 회사 사납금 규칙 다름" | ③driver_settings 값 | 없음(값) |
| "이번 주 수락률 통계" | ⑤AI lens(읽기) | 카드 한 줄 |
| "콜 잘 잡히는 곳 공유" | 집단지성 source→핫존 | 소스/집계 |
| "격일제 근무도 지원" | ③workTimeMode 값 확장 | 값(bands) |
| "가스 말고 전기차 충전비" | ④expense + ②영수증 source | 항목/소스 한 줄 |

→ 8개 중 본체(HomeScreen·병합엔진·계산코어) 수정이 필요한 건 **0개.** 전부 한 줄/값.

---

## 5. 반박 / 자기비판
- **"진짜 모든 아이디어가 5개로 떨어질까?"** — 아니다. 그래서 §3 경고신호를 뒀다. 안 떨어지는 게 나오면 그건 **나쁜 게 아니라 신호** — 새 뼈대를 진지하게 볼 때. 5문항은 "대부분"을 싸게 처리하고 "진짜 큰 것"만 걸러내는 필터다.
- **"유저 요청 다 받으면 비대해짐?"** — 흡수 ≠ 다 켬. 등록소에 있어도 `defaultVisible`·`slot`으로 노출 조절. 넣되 조용히. (헌장 5)

---

## 6. 뼈대 연결 (이 절차가 기대는 것)
- **화면 등록소 v2**(카드) · **멀티소스**(소스) · **driver_type/설정값** · **수입·지출 항목/토글** · **AI source·lens** · **자가복구**(어떤 흡수든 데이터는 안전).
- 최상위 **설계헌장** 7원칙을 항상 통과.

---

## 7. 검증 체크리스트 (아이디어 하나 넣을 때마다)
- [ ] 5문항 중 하나로 분류됐나?
- [ ] 흡수가 등록소 한 줄 / 값 하나로 됐나(본체 무수정)?
- [ ] 규격·소스를 억지로 늘리지 않았나?
- [ ] 넣되 노출은 조절했나(비대화 방지)?
- [ ] 설계헌장 7원칙을 통과했나?
- [ ] 안 떨어지는 아이디어를 "새 뼈대 신호"로 다뤘나(우겨넣지 않았나)?
