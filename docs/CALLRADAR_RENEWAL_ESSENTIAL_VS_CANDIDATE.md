# CallRadar 리뉴얼 — 필수 구현 / 검토 후보 구분

작성: 2026-10-05 KST
근거: 지시서 「전체 리뉴얼 개발 후 통합 후보 설치」 — "R01~R18에서 필수 구현과 검토 후보를 구분하고,
합의한 필수 기능이 연결된 release 후보를 완성하라."

판정 기준
- **필수(E)** = 없으면 숫자가 틀리거나 자료가 유실되거나 기사가 손해를 본다. 통합 후보에 반드시 들어간다.
- **후보(C)** = 있으면 좋지만, 없어도 틀린 숫자를 만들지 않는다. 또는 외부 확인·측정·승인이 선행이라
  이번 후보에서 결정할 수 없다. 통합 후보에서 **빠지거나, 자료 부족 표시 상태로만** 들어간다.
- 가격·조회기간은 지시대로 **설정 가능한 모의 권한**으로만 구현하고 실제 과금은 활성화하지 않는다.

## 3. 지금까지 완료된 것의 증거

**순수 함수 + 정답 fixture: 41건 전부 통과** (`server/calc/`, `node calc/test/run.js`)

```
server/calc/value.js      값과 품질 (confirmed/estimated/unknown/pending, sum/subtract/ratio)
server/calc/bizday.js     영업일 경계, 구간 자르기(원본 보존), merge
server/calc/worktime.js   근무/운행/비실차 분리, activeHours 폴백, 시급
server/calc/waitstats.js  관측·검열·미상 3분할, 조건부 평균, 하한 평균, 충분성
server/calc/money.js      기록된 매출, 통행료 부담주체, 비용 품질등급, 수수료 보류, 하루 순수익
server/calc/test/run.js   정답 fixture 41건
```

테스트에 실제 자료를 썼다 — 2026-10-05 user 1 의 운행 5건으로 **기록된 매출 44,700원** 이
운영 `/api/today/1` 과 일치하는 것을 fixture 로 고정했다. 이것이 기존·새 계산 병행 검산의 첫 기준점이다.

**임계값은 넣지 않았다.** `waitstats.PROVISIONAL` 은 `provisional: true` 로 표시되고,
테스트도 "임계값은 잠정값" 을 검사한다. 지시서의 "구체적인 필터·임계값·운영 숫자 전환은 측정 후 확정" 을
코드 수준에서 지키기 위한 장치다.

**빌드 산출물** (기존 기준 빌드는 비교용으로 보존)
```
BASELINE_app-onestore-debug_e7c61ec.apk   sha256 d016294234aba65be19ac1ee4f21ef4f932a6a39fb00724089e61adb495c2d8c
app-onestore-release.apk  (111 / 3.1.1-onestore)  2026-10-05 15:23 재빌드

```

**최종 APK 로 확인한 사실 (정정 포함)** — 두 flavor 모두 `NaviIntentReceiver` 를 싣는다.
`app/src/play/AndroidManifest.xml` 에 2026-08-28 대표 결정으로 play flavor 접근성 선언이
들어가 있고, 비공개 테스트 트랙 전용이라고 그 파일에 적혀 있다. `onestore` 매니페스트의
"Play 빌드에는 절대 포함되지 않음" 주석은 그 결정 이전에 쓰인 것이라 지금은 사실과 다르다.
따라서 E2 결함의 영향 집단은 flavor 가 아니라 **접근성을 끈/허용하지 않은 기사**다.

## 4. 검증 환경 (지시: 로컬 PostgreSQL + 로컬 서버)

- PostgreSQL 17.6 Windows 바이너리(무설치 zip)를 `C:\pgverify\pg` 로 받는다 — 서비스 등록·관리자 권한 없음
- 데이터 디렉터리 `C:\pgverify\data`, 포트 **5433** (운영/다른 Postgres 와 충돌 방지)
- 검증 DB `callradar_verify`. 스키마는 `server/index.js` 가 기동 시 `CREATE TABLE IF NOT EXISTS` /
  `ALTER TABLE ... ADD COLUMN IF NOT EXISTS` 로 **자기 스키마를 만든다** → 운영 스키마와 같은 모양이 보장된다
- 로컬 서버는 포트 **3001**. 앱은 `Config.SERVER_URL` 전환으로 붙인다
- **운영 원본은 수정하지 않는다.** 검증 DB 에는 합성 자료만 넣는다

용도
1. R02/R03 실패 주입 — 오프라인·4xx·5xx·타임아웃·부분 저장
2. C6(진짜 ACK) / C7(`work-session/close`) / E18(`calc_version`) 의 서버 변경을 **운영 전에** 입증
3. E12 연결 후 기존·새 계산 병행 검산
