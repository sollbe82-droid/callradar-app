## 1. 정체성 & 북극성 (모든 판단의 뿌리)
- **현직 택시기사 루이(이영진)가 자기 불편을 풀려고, 기사 요구에 맞춰 직접 만드는 앱.** 외부 개발사가 못 흉내내는 해자 = 현장 도메인 + 타협 없는 설계 규율.
- **북극성:** "누가 써도 간편하다, 좋다 — 이거 왜 이제 나왔냐." 기능 수가 아니라 이 반응이 목표. 모든 결정의 최종 필터.
- **경쟁 차별(티머니 택시투데이 등):** 현금·길빵 통합 · 급여 역산 · 회사-기사 정산 대시보드(B2B) · 핫존 AI.

## 2. 심장 루프 (한 문장 — 이거 먼저 기억)
플랫폼이 제각각(카카오T·우버·티머니고) → **①무입력 자동취합**(여러 플랫폼 운행을 손 안 대고 한 원장으로 자동기록) → **②콜 수락 순간 감지** → **③비식별 집계로 핫존 지도**(적/황/청) → **④무료 유저 제보가 예측을 키우고, 정밀 예측은 유료.**
→ 핵심: **자동기록은 가계부가 아니라 핫존의 연료.** 자동기록 없으면 수락감지·핫존 없음.

## 3. 설계헌장 7원칙 (docs/01 · 모든 설계가 통과)
① 뼈대 먼저, 기능 나중(한 줄 흡수·본체 불변) ② 단순함이 최고 기술 ③ 데이터는 신성(서버=진실·불변추가형·백업) ④ 정체성이 최종 판단 ⑤ 덜어내는 용기 ⑥ 조잡하지 않게=일관성(카드 3규격·한 톤) ⑦ 실수는 '안 하기'가 아니라 '잡기'(무결성·롤백·체크리스트).
- **예스맨 금지:** 아이디어 받으면 항상 [최적안 → 반박/대안(내 안을 내가 깜) → 뼈대 연결 → 검증 체크리스트].

## 4. 4대 확장 뼈대 (docs/02·03·04 + 등록소 · 본체 불변·한 줄로 흡수)
- **멀티소스 기록(02):** 운행(Trip) = 기여(Contribution)들의 **파생(projection)**. GPS·전표(meter)·현금(cash)·수동(manual)·(나중)스샷·BLE·AI = source 한 줄씩. **유저 수동정정 precedence 999 = 항상 최고**(자동이 못 덮음). 파생은 순수함수 → 손상 시 재계산=자가치유.
- **자가복구(03):** 서버=진실, 폰=캐시, 불변·추가형, 클라 UUID 멱등, 오삭제 복구. 멀티소스와 **같은 등뼈**.
- **driver_type 축(04):** `personal`/`corporate`(+`cooperative` 자리만 예약) + **능력 플래그**(hasQuota·fuelSettlement·submitReceipts·workTimeMode·taxMode·receiptArchive). 코드는 유형 문자열이 아니라 **플래그를 봐야** 함(if 분기 폭발 방지). ※네이밍 통일 미결(코드 personal/corporate ↔ 설계 private/corp).
- **화면 등록소 v2 = "튜닝모드":** 기사가 홈·탭 카드를 직접 켜고/끄고/순서 바꿈. 3규격·한 톤 유지, minRole로 유형별 자동노출/숨김. ※**설계문서 실물이 정본에 없음(구멍, 복원 필요)**.
- **아이디어 흡수 5문항(08):** ①화면? →카드 ②새입력/데이터? →source ③유형별 규칙? →driver_settings/플래그 ④새 수입·지출·계산? →entry type/토글 ⑤읽거나 물어봄? →AI lens/source. 어디에도 안 걸리면 = **새 뼈대 신호**(우겨넣지 말 것).

## 5. AI "스며든 AI" (docs/06 · 별도기능 아님, 뼈대의 두 갈래)
- **source(쓰기·확인형):** 스샷 만능입력 → `ai` source 기여로 흡수, confidence 낮으면 "확인 필요"(자동확정 금지).
- **lens(읽기전용):** 자연어 수입질문·백그라운드 인사이트. **절대 안 씀**(금융데이터 변경은 승인 필요).
- **집단지성:** 콜 제보 사진 → 서버 집계 → 핫존(개인식별 제거).
- **비용 게이트:** 규칙으로 되면 무료(온디바이스)·자유형식만 AI 유료(일일한도). 기본은 조용함.

## 6. 완전자동화 = 특허 = 유료화 핵심 ★가장 중요
- **v6까지 완전자동판(NaviIntentReceiver 접근성)이 테스터 3명으로 실작동했음.** 시작/종료 감지 성공, 금액 자동입력 95%(카카오·티머니 100%, **우버만 약간 오류**).
- **나눈 이유는 오직 Play 심사**(접근성 스크래핑=밴 리스크). 개인 APK로는 문제 없었음. **목표 = 별도 APK 배포가 아니라 완전자동판을 스토어에 올리는 것 = 최종 상업적 가치 = 유료화.**
- **심사 통과 경로:** 포그라운드+플로팅 위젯 단계화 → **네비 인텐트/브로드캐스트로 목적지 취득(접근성 스크래핑 회피)** → 지오펜스+활동인식 자동종료 → 금액은 전표 OCR + MediaProjection 동의기반 스샷. **BLE는 뺌**(제조사 제휴만 가능).
- **특허(가출원·우선일 확보):** 12발명. 발명1=무입력 자동수집(접근성/이벤트·FORCE_END/CANCEL_END·Knox하이브리드·GPS동적), 발명2=정규화(최대금액·"14,400"통화생략·다중소스합산), 발명3=핫존/수락률/공항·이벤트연동, 발명4=개인세무, 발명5=법인정산, 발명6=게임화·동적UI, **발명7=순수익 콜의사결정(무자동수락·정보제공=약관위반X)**, 8=귀로호출·10=신뢰도검증·11=신용·12=산업중개.
- **결론:** 제품 변경은 특허 무효화 안 함. 심사용 "무자동수락·정보제공" 설계가 **이미 발명7에 서술** → 심사통과=특허 정합.
- **변리사 챙길 것:** ⏰정식출원 12개월 시계 · 📢플레이 출시=공개 → 공지예외 주장 · 🔒청구항을 접근성+인텐트+MediaProjection+지오펜스 다 커버.
