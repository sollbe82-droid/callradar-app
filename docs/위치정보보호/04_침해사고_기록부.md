# 위치정보 침해사고 기록부

> 근거: 위치정보처리지침 제13조·제14조 (고시 제5조 ① 4호)
> 침해사고 또는 그 우려를 발견하면 **즉시** 여기 기록한다. 조치가 끝난 뒤에 몰아 쓰지 않는다.

## 기록 규칙

- **발견 즉시 적는다.** 원인을 다 밝힌 뒤에 쓰려고 미루면 초기 정황이 사라진다.
- **범위를 단정하지 않는다.** 확인된 것과 추정을 구분해 적는다.
- **차단이 먼저다.** 원인 분석보다 경로 차단을 먼저 하고, 그 시각을 적는다.

## 제1호 — 2026-08-27 · 예약 조회 인증 누락 (IDOR)

| 항목 | 내용 |
|---|---|
| **발견일시** | 2026-08-27 (KST) |
| **발견 경위** | 외부 전송 경로 전수조사 중 코드 검토로 발견 |
| **유형** | 권한 없는 접근 가능 상태 (실제 유출 확인되지 않음) |
| **대상 정보** | 예약 승객의 **성명·연락처** (개인정보). 위치정보는 미포함 |

**내용**

`GET /api/bookings/:driverUserId` 에 인증 검사가 없었다.
`user_id` 가 1부터 순번이라 값을 바꿔가며 호출하면 다른 기사의 예약 목록을 읽을 수 있었다.
같은 파일의 상태변경 API 는 토큰 검사를 하고 있었으나 **조회 경로에만 빠져 있었다.**

**확인된 범위**

| 항목 | 값 |
|---|---|
| 전체 예약 건수 | 8건 |
| 연락처 포함 | 8건 |
| 관련 기사 수 | 5명 |
| 기간 | 2026-07-27 ~ 2026-08-23 |

실제 무단 조회가 있었다는 정황은 발견되지 않았다.
다만 당시에는 접근기록이 없었으므로 **"없었다"고 단정할 수는 없다.**

**조치**

| 시점 | 내용 |
|---|---|
| 당일 | 토큰 인증 필수로 변경. 본인 것만 조회 가능(401/403). 실측 확인 |
| 당일 | 90일 경과 예약의 성명·연락처·메모 자동 파기 도입 |
| 당일 | 예약 페이지에 승객 대상 개인정보 수집 고지 추가 |
| 당일 | 관리자 접근기록(`admin_access_log`) 도입 — 이후 동종 사고는 추적 가능 |

**재발 방지**

- 조회 API 를 만들 때 **인증을 기본으로** 두고, 공개가 필요한 경우에만 예외로 뺀다.
- 인증 검사 로직을 `requireAdmin` 등 **한 곳으로 모은다.** 흩어져 있으면 한 곳을 고쳐도 남는다.
- 개발 게이트(정관 3-1)에 개인정보·법령 관문을 신설했다.

## 제2호 — 2026-08-27 · 사진의 국외 전송과 방침 불일치

| 항목 | 내용 |
|---|---|
| **발견일시** | 2026-08-27 (KST) |
| **유형** | 고지 없는 처리위탁·국외이전 (유출 아님) |
| **대상 정보** | 영수증·전표 사진 (개인정보 해당 소지) |

**내용**

지출 영수증 사진이 Cloudinary(미국)에 업로드되고, 그 주소를 Anthropic(미국)이
가져가 판독하고 있었다. 그러나 개인정보처리방침 제5조 수탁자 표에는 Render·카카오만
기재되어 있었고, 제4조에는 "제3자에게 제공하지 않습니다"라고 적혀 있었다.
**문서와 실제 동작이 어긋난 상태로 두 스토어에 배포되어 있었다.**

추가로 업로드된 사진은 삭제 경로가 없었고, unsigned 방식이라 **주소를 알면 로그인 없이
열람 가능**한 상태였다. 저장량 197MB(약 400장 추정).

**확인된 범위**

최근 30일 조회수 0, 대역폭 0 — 외부에서 열람된 정황은 발견되지 않았다.

**조치**

| 시점 | 내용 |
|---|---|
| 당일 | 서버 게이트로 AI 판독 2경로 중지(503) |
| 당일 | Cloudinary preset 을 Signed 로 잠금 — 업로드 차단 실측 확인(400) |
| 당일 | 앱의 업로드 호출 제거 |
| 당일 | 온디바이스 좌표 기반 판독으로 대체 — 사진이 폰을 떠나지 않음 |
| 예정 | 기존 업로드 사진 파기 |
| 예정 | 방침에 수탁자·국외이전 조항 정비 |

**재발 방지**

- `tools/check-outbound.js` — 코드의 외부 호스트를 허용목록과 대조. 미등재면 실패.
- `tools/check-secrets.js` — 자사 자격증명 유출·키 하드코딩 검사.
- 정관 9-5 — 사진·개인데이터 처리 계층 원칙(폰 안 → 자사 서버 → 제3자 순).
