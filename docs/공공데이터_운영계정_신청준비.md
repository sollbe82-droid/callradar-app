## 1. 신청 대상 3종 — 우선순위 순

| 순위 | 데이터셋 | 번호 | 현재 호출량 | 개발계정 1,000 대비 |
|---|---|---|---:|---|
| 1 | 인천국제공항공사_택시출차 정보 | 15095062 | **576회/일** | **58% — 가장 급함** |
| 2 | 인천국제공항공사_입국장현황 정보 서비스 | 15095061 | 192회/일 | 19% |
| 3 | 인천국제공항공사_승객예고-출·입국장별 | 15095066 | 58회/일 | 6% |

**운영계정 트래픽: 일 1,000,000** (개발계정의 1,000배)
**심의: 개발단계·운영단계 모두 자동승인** — 즉시 처리됩니다.
단 **"활용사례 등록 시 신청하면 트래픽 증가 가능"** 이라고 명시돼 있으니
**활용사례 등록을 먼저 하고 운영계정을 신청**하는 순서가 맞습니다.

### 왜 3번(승객예고)도 신청하나 — 지금은 6%인데
호출량이 적어서가 아니라 **가장 중요한 데이터**이기 때문입니다.
앱의 '예상 혼잡도' 화면 전체가 이 데이터로 돌아갑니다.
도착편 API는 이미 도착했거나 임박한 편만 주기 때문에 미래 수요를 만들 수 없고,
그 자리를 승객예고가 대신합니다. 이게 끊기면 화면이 통째로 빕니다.

## 2. 운영계정 신청서에 적을 내용 (공통)

### 활용목적
```
택시기사 대상 무료 앱 '콜레이더'에서 인천공항 방면 공차 운행을 줄이기 위한
실시간 수요 정보 제공. 광고·인앱결제 없음.
```

### 활용내용 (상세)
```
택시기사는 손님을 내린 뒤 다음 행선지를 매번 감으로 판단합니다.
인천공항은 왕복 2시간이 걸리는 장거리라, 대기 택시가 이미 많은 상태에서
공차로 이동하면 그 시간과 연료비를 그대로 손해 봅니다.

콜레이더는 아래 3종을 조합해 이 판단을 수치로 바꿉니다.

1) 택시출차 정보 (15095062)
   제1·제2여객터미널의 일반·모범·대형 택시 대기 대수를 5분 주기로 수집해
   "지금 공항에 가면 몇 대 뒤에 서는지"를 그대로 보여줍니다.

2) 입국장현황 정보 서비스 (15095061)
   도착 예정 항공편의 편명·예정시각·실제시각·터미널·입국장을 15분 주기로 수집해
   기사가 어느 터미널 어느 입국장으로 갈지 정하는 데 사용합니다.

3) 승객예고-출·입국장별 (15095066)
   시간대별 예상 입국 인원을 25분 주기로 수집해, 분 단위로 안분하여
   "지금부터 30분 내 / 1시간 내 도착 예정 인원"으로 환산합니다.
   기사가 이동시간(30/45/60분)을 고르면 본인이 도착할 시점의 예상 규모를
   강조해 보여줍니다.

수집한 데이터는 서버에 5~15분 캐시로만 보관하며 재배포하지 않습니다.
동시 요청은 서버에서 병합(single-flight)하여 중복 호출을 막고 있습니다.
```

### 예상 트래픽 산정 근거
```
택시출차   5분 주기 × 2터미널 = 576회/일
입국장현황 15분 주기 × 2터미널 = 192회/일
승객예고   25분 주기          = 58회/일

사용자가 늘어도 앱은 서버 캐시를 보므로 upstream 호출량은 증가하지 않습니다.
다만 장애·재시도 상황을 감안해 여유 한도를 요청합니다.
```

### 시스템 구성
```
Android 앱(Kotlin) → 자체 서버(Node.js/Express, Render) → 공공데이터포털 오픈API
앱은 공공데이터를 직접 호출하지 않습니다. 서버가 대표로 호출하고 캐시합니다.
```

## 3. ★ 승객예고 — 관리부서 협의용 자료

앱이 **실제로 화면에 쓰고 있는 문구 전수**입니다. 협의 시 이대로 제출하면 됩니다.

### 화면에 표시되는 문구

| 위치 | 문구 |
|---|---|
| 카드 제목 | `T1 입국심사 진행 인원` |
| 값 아래 | `현재 입국장으로 들어오는 승객 규모입니다` |
| 예측값 | `30분 내 도착 예정` / `1시간 내 도착 예정` |
| 카드 제목 | `T1 시간대별 입국 예고 (꾹 눌러 공유)` |
| 부제 | `오늘 예상 입국 승객 (인천공항 승객예고)` |
| 캡션 | `막대가 길수록 그 시간대 입국 손님이 많아요 · 지금은 10시` |
| 카드 제목 | `T1 앞으로 도착 손님 (30분 단위)` |
| 캡션 | `인천공항 승객예고 기준 · 노란 줄이 내가 도착할 시간대` |
| 데이터 없음 | `입국 예고를 아직 못 받았어요. 위 새로고침을 눌러 주세요.` |
| 부분 실패 | `입국심사 인원만 못 가져왔어요` |

### 협의에서 강조할 점 — 우리가 이미 지키고 있는 것

**① 출처를 화면에 명시합니다.**
`(인천공항 승객예고)`, `인천공항 승객예고 기준` 을 카드마다 붙였습니다.

**② '예상'임을 문구에 담았습니다.**
`예상 입국 승객`, `도착 예정`, `예고` — 실측이라고 쓰지 않습니다.

**③ 못 받은 값을 0으로 표시하지 않습니다.**
데이터를 못 받으면 숫자 대신 `정보 없음`과 사유를 띄웁니다.
0으로 보여주면 기사가 "손님이 없다"로 오해해 잘못된 판단을 하기 때문입니다.
부분 실패도 구분합니다 — 택시는 정상인데 입국 인원만 못 받으면 그것만 짚어 안내합니다.

**④ 승객 개인정보를 다루지 않습니다.**
시간대별 집계 인원만 사용하며, 개별 승객 정보는 수집·저장·표시하지 않습니다.

**⑤ 재배포하지 않습니다.**
서버 캐시(5~15분) 외에 원본을 저장하거나 제3자에게 제공하지 않습니다.
