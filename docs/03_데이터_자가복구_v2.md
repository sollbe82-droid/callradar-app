# 콜레이더 — 데이터 자가복구 · 자동 유지보수 설계 · v2
*작성 2026-07-21 · v1 대체·승격 · 멀티소스 기록과 통합 · 서버=진실*

> v1 대비 바뀐 것: ① 서버=진실을 1순위로 승격 ② **금융 저널 = 멀티소스 기여(Contribution)로 통합**(따로 안 만듦) ③ 멱등 동기화·투폰 충돌 해소 ④ 무결성=재계산 ⑤ 마이그레이션 expand-and-contract ⑥ 테스트된 백업.
> 대원칙(불변): **코어가 '보장', AI는 '똑똑하게' 얹기. AI는 승인 없이 금융데이터를 안 바꾼다.**

## 0. 막을 위협 3종
① 업데이트/마이그레이션 사고 ② 앱·기기 손상/분실 ③ 유저 실수(삭제·오입력).

---

## 1. 핵심 재설계 — 서버가 진실, 폰은 캐시
- 서버를 원본으로 두고 모든 변경을 계속 동기화. **폰이 깨지거나 초기화돼도 서버에서 다시 당기면 복구 끝.**
- 로컬 이벤트 리플레이보다 **단순하고 강함.** 솔로 개발자에겐 단순함이 곧 안 깨짐. (헌장 원칙 2)
- + "내 데이터 내보내기"(PDF·엑셀·이메일) = 데이터 인질 안 잡는 신뢰.

---

## 2. 금융 저널 = 멀티소스 기여 (따로 안 만든다)
자가복구의 "이벤트 저널"과 멀티소스의 "기여(Contribution)"는 **같은 것.**
- 운행·수입은 덮어쓰지 않고 **불변·추가형 기여**로만 쌓임.
- 보이는 값은 파생(projection) → **손상 시 기여에서 재계산 = 자가치유.**
- 범위 축소: **금융(운행·수입·경비)만** 이 저널. 사소한 설정은 평범한 값. (event-sourcing 톤다운)

### 멱등 동기화 (투폰·끊긴 네트워크)
- 기여마다 **클라이언트 생성 UUID.** 재전송해도 같은 UUID면 한 번만 → **중복 입력 방지.**
- 투폰(같은 카카오 id 두 기기) 오프라인 기록도 **불변·추가형이라 병합=합집합** → 충돌·유실 없음.

---

## 3. 확실한 코어 (AI 아님, 필수)
1. **불변·추가형 기여 저널** (= 멀티소스). 파괴적 덮어쓰기 금지.
2. **자동 스냅샷/백업** — 주기적 + **업데이트·마이그레이션 직전** 자동.
3. **마이그레이션 = expand-and-contract** — 새 컬럼/테이블 추가 → 백필 → 나중에 옛것 제거. **파괴적 변경 금지 → 실패해도 원본이 안 죽음.** (트랜잭션+롤백보다 근본적으로 안전)
4. **무결성 = 재계산 대조** — 불변식: *화면 합계 == 기여들의 재계산.* 실행 시 체크섬 비교, 어긋나면 조용히 넘기지 말고 알림.
5. **소프트 삭제(휴지통)+되돌리기** — 유저 실수는 즉시 소멸 아님. 기여 `status`를 `rejected`로(실제 삭제 아님), N일 내 원터치 복구.
6. **테스트된 백업** — 가끔 백업을 스크래치에 **실제 복원해 무결성 확인.** 안 테스트한 백업은 없는 백업.

---

## 4. AI 층 (코어 위, '스며든 AI')
- **규칙 먼저, AI 나중:** "8시간 운행했는데 수입 0" 같은 건 **규칙**이 90% 잡음(오프라인·무환각).
- **이상 감지(규칙→AI):** "오늘 수입이 평소 1/10인데 입력 빠진 거 아니에요?", "이 전표 중복 같아요."
- **대사 제안:** 멀티소스 매칭이 애매하면(전표 다건) "이 금액은 이 운행 같아요" **제안** → 유저 승인.
- **가이드 복구:** 손상 감지 시 쉬운 말 설명 + "7월 20일 백업으로 되돌릴까요?" 원터치.
- **철칙:** 전부 **제안형.** AI는 승인 없이 금융데이터를 안 바꾼다. 모든 자동 변경은 로그로 되돌리기 가능.

---

## 5. 유저에게 보이는 모습
- 평소: 안 보임(조용한 백업·검사).
- 문제 시: 친절한 카드 한 장("데이터가 좀 이상해요. 되돌릴까요?").
- 설정 "데이터 안전" 화면: 마지막 백업 시각 · 복구 지점 · 내보내기 · 휴지통.

---

## 6. 뼈대 연결
- **멀티소스 기록:** 저널을 공유(같은 등뼈).
- **driver_type:** taxMode='sole_proprietor'(개인택시)면 세무·영수증 5년 무결성 특히 중요.
- **화면 등록소 v2:** "데이터 안전" 카드 한 줄(settings surface).
- **정체성:** 데이터 안 잃고 안 틀림 = 신뢰 = 해자.

---

## 7. 구현 순서 (조용한 것부터)
1. 서버=진실 동기화 + 기여 저널(=멀티소스와 공유) + 멱등 UUID.
2. 자동 백업(마이그레이션 직전) + expand-and-contract + 실행 시 무결성 재계산.
3. 소프트 삭제/휴지통 + 되돌리기 + 내보내기.
4. 규칙기반 이상감지 → (나중) AI 제안.

## 8. 검증 체크리스트

- [ ] 같은 UUID 기여 재전송이 중복을 안 만드나(멱등)?
- [ ] 투폰 오프라인 기록이 합집합으로 병합되어 유실이 없나?
- [ ] 마이그레이션이 파괴적이지 않아(expand-and-contract) 실패해도 원본이 사나?
- [ ] 화면 합계가 기여 재계산과 일치하나(무결성)? 어긋나면 알리나?
- [ ] 유저가 하루치 삭제해도 N일 내 원터치 복구되나(휴지통)?
- [ ] 백업이 실제 복원 테스트로 검증되나?
- [ ] AI는 승인 없이 금융데이터를 절대 안 바꾸나(제안만)?
