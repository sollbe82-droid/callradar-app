## 2. 오늘 발견한 핵심 인사이트

- **텔레메트리 "4명"은 오해였음.** 실제 데이터 유저 **21명**, 그중 **13명이 10건+ 단골**, 총 운행 **1,179건**.
- **진짜 문제 = 활성화(첫 운행).** 가입 106명 중 **85명(80%)이 운행 0건**. 반면 첫 운행 넘긴 21명 중 13명(62%)이 단골로 정착 → **유지력은 좋고, 입구에서 샌다.**
- 가입 79명이 7/19 한 주에 몰림(홍보 유입) → 대부분 첫 운행 없이 이탈.
- **원인 가설:** 홍보글이 "버튼만 누르면 자동 기록 / 전표 찍으면 매출 자동"을 강조했는데, 실제는 (1) 플로팅 버튼 권한 설정 마찰, (2) OCR 인식률 낮음, (3) 자동 금액매칭 미출시 → 체감이 수동 → 이탈. (기대 vs 실제 간극)

## 3. 카피앱 방어 전략 (요약)

- **특허**: 개념·UI 아니고 **구체적 방법**(OCR→GPS 금액매칭, 정밀도 계층 수요집계 등)만 보호. 회피설계 가능 → 만능 아님, 억지력. **변리사 상담 필요**(우선심사 등).
- **역설계 방지**: APK는 항상 디컴파일됨. → **핵심 로직을 서버에 유지**(이미 대부분 서버). 난독화(R8)는 보조.
- **함정기술(honeypot)**: 카피 "탐지·증명"용(워터마크/가짜 시드). 보조.
- **진짜 해자**: 코드 아니라 **데이터·커뮤니티·실행 속도** + 네트워크 효과(유저 많을수록 정확해지는 콜 히트맵).
- **권고**: 난독화·풀 인증은 출시 후. 지금은 서버 rate limit(저위험)만.

## 8. 알림 자동캡처(금액 자동입력) — phase-2 켜기/끄기

**목적:** 카드결제(택시투데이 "[택시승인] N원")·티머니GO 결제 알림을 읽어 금액을 자동 입력 → 손 안 감. (카카오T 앱내 자동결제는 택시투데이 알림 안 옴.)
**스토어 리스크:** 다른 앱 알림 읽기(NotificationListenerService)는 첫 심사에 민감 → v18/19엔 **미포함**. 자동화 차수에서만.

**켜는 법 (phase-2, 사이드로드/자동화 심사):**
1. `app/src/main/AndroidManifest.xml` — `CallCaptureService` `<service>` 블록 주석 해제.
2. `app/src/main/java/com/callradar/app/screen/Config.kt` — `NOTIF_CAPTURE_ENABLED = true`.
3. 빌드·설치 → 홈 "💰 금액 자동 입력" 켜기 → 알림 접근 권한 허용.

**끄는 법 (스토어 심사용, 현재 상태):** 위 둘을 반대로(주석 처리 + false). 지금이 이 상태 = v18/19 안전.

**실물 학습:** 켠 뒤 실제 결제 알림이 오면 서버 `notif_samples` 테이블에 문구가 쌓임 → 그걸 보고 파서(금액 추출·완료 판정) 정밀 튜닝. 옛 `TmoneyNotificationService.kt`에 검증된 패턴("택시승인/택시결제", 마지막 원 매치, 60초 쿨다운) 있음.
