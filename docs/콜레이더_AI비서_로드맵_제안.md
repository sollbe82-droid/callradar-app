# 콜레이더 AI 운행 비서 — 확장 로드맵 (대표 제안)

> 대표(루이) 아이디어 + Claude(대표 대행) 제안. 정관 3장 게이트(특허·FTO) 및 "구라 없게" 원칙 적용.
> 핵심 축: **운행 데이터 + 제보(스샷 OCR·교정) + 이벤트**를 결합해, 데이터가 쌓일수록 똑똑해지는 개인 비서. 무료 체험 → 구독 전환의 가치가 여기서 나온다.

---

## A. 대표 아이디어 (채택·구체화)

### A-1. 지도(핫스팟 히트맵)
- 자주 잡히는 포인트를 **지도 위 히트맵**으로. 지금은 텍스트 목록 → 나중에 지도.
- 실현성: **Kakao Map SDK(한국 특화·무료 티어)** 권장(구글맵보다 KR 적합). 키 필요(Render/앱 설정).
- 정직: 데이터 밀도 낮으면 히트맵 흐릿 → "표본 적음" 배지. 초기엔 내 기록 위주.
- 특허/FTO: 지도 표시 자체는 신규성 없음. **"크라우드 교정 수요예측을 히트맵+시간대로 표출"** 결합만 청구 범위 후보.

### A-2. 음성 안내 On/Off (TTS)
- 운전 중 **핸즈프리 음성 안내**("여기 근처, 22시엔 서울행 귀로콜 자주 나와요"). 안전(시선 유지)에 직결.
- 실현성: **안드로이드 TextToSpeech(온디바이스·무료)**. 쉽고 빠름. 설정에 On/Off + 볼륨.
- 정직: 안내할 "분석"이 있어야 의미 → A-4/B-1과 함께 켜짐. 데이터 없으면 음성도 침묵.
- 특허/FTO: TTS는 범용. 결합(수요예측→음성 트리거)만 부수 청구.

### A-3. GPS 지역 진입 자동 인식 → 알림/분석
- 특정 지역(지오펜스) **진입 시 자동으로** "이 지역·이 시간대 콜 패턴" 알림.
- 실현성: 안드로이드 **Geofencing API**. ⚠️ 정관 9장 교훈: v9 GPS 배터리 과소모 → **저전력(코스 위치·이벤트 기반)** 으로 가볍게. 요금 자동추정은 절대 안 함(과거 버그).
- 정직: 콜을 "중개"하지 않음(우리는 플랫폼 아님). "정보 제공"만.
- 특허/FTO: **[특허후보]** 지오펜스 진입 트리거 + 크라우드 교정 수요예측 결합 = 신규성 여지. 변리사 검토.

## B. Claude(대표 대행) 추가 제안 — 신규 아이디어

### B-1. 귀로콜 레이더 (시그니처 기능) ⭐
- 기사가 **시외에서 하차**하면 자동 감지 → "여기서 귀로/장거리 콜이 잘 나오는 시간·지점"을 데이터로 안내. **시외 공차 귀환(가장 큰 손해)** 을 줄여줌.
- 왜 킬러: 기사 최대 고통 = 시외 갔다가 빈 차로 복귀. 이걸 줄이면 **바로 돈**. 구독 가치의 핵심.
- 실현성: A-3(지오펜스) + 핫스팟 집계 + 이벤트. 이미 만든 파이프라인 위에 얹음.
- 특허/FTO: **[특허후보·강함]** 정관 4장 "수요예측 피드"와 결합. 핵심 청구 대상.

### B-2. 다음-콜 방향 추천 (공차 최소화)
- 하차 후 "다음 콜 확률 높은 방향" 힌트(내 패턴 + 집계). **확률/정보 제공**이지 배차 아님.
- 실현성: 집계 쿼리 확장. 정직: 확률은 표본 표기와 함께.
- 특허/FTO: B-1의 하위. 별도 신규성 약함.

### B-3. 음성 핸즈프리 로깅 ⭐
- 운전 중 **"강남에서 콜 잡았어"** 음성 → 자동 기록/제보. 타이핑 위험·귀찮음 해결 + 제보 참여 급증.
- 실현성: 안드로이드 SpeechRecognizer(온디바이스 가능). A-2와 짝. 정직: 인식 실패 시 조용히 무시, 초반 정확도 낮음 명시.
- 특허/FTO: **[특허후보]** 음성→구조화→수요말뭉치 결합. 부수 청구 후보.

### B-4. 이벤트 연동 수요 푸시 ⭐ (즉시성 높음)
- "오늘 22시 잠실 야구 종료 → 그 지역 콜 급증 예상, 지금 이동 20분". **이미 만든 이벤트 데이터** + 교통/시간.
- 실현성: 이벤트 파이프라인 이미 있음 → 알림 스케줄만. 근거 없는 수치 금지(정관 9장) → "예상"으로 표기, 실제 집계로 보정.
- 특허/FTO: 이벤트→수요 피드는 정관 후보에 이미 있음.

### B-5. 개인 운행 리듬 인사이트 (Day-1 가치) ⭐
- "당신은 **목요일 22–24시** 매출 최고", "화요일 오전은 낮음" 등 **본인 데이터만으로** 즉시 유용. 집계가 적어도 첫날부터 가치 → 무료 체험 붙잡기.
- 실현성: 서버에 개인 통계 쿼리(이미 유사 통계 있음). 쉬움.
- 특허/FTO: 개인 통계는 범용. 특허 대상 아님(가치는 습관화).

### B-6. 안전 모드 (규제·지원사업 유리)
- 이동 중엔 **화면 입력 최소화, 음성·간단 알림 위주**. 안전 프레임은 투자/지원사업 심사에 플러스.
- 특허 아님(정책/UX).

## C. 추천 개발 순서 (대표 의견)

1. **B-5 개인 리듬 인사이트** — 가장 쉽고 Day-1 가치, 무료체험 붙잡기. (서버 개인통계 + AI 비서 카드)
2. **B-4 이벤트 수요 푸시** — 이벤트 데이터 이미 있음, 즉시성.
3. **A-2 음성 안내 On/Off (TTS)** — 안전, 위 안내들을 음성으로.
4. **A-3 지오펜스 + B-1 귀로콜 레이더** — 시그니처 킬러(배터리 주의). 특허 핵심.
5. **B-3 음성 로깅** — 제보 참여 폭증.
6. **A-1 지도 히트맵** — 데이터 밀도 오르면.

> 구독 매핑: 무료체험 = B-5 + 핫스팟. 구독 = 귀로콜 레이더(B-1) + 이벤트 푸시(B-4) + 음성(A-2/B-3).

## D. UI 재설계 후속 순서 (대표 지시: 1·2·3·4 전부 진행)
기본 재설계(홈=오늘 중심 / 기록=내역·달력·지출·월급[실금액]) 완료. 남은 것:
1. **예쁜 운행기록 카드뷰**(#41) — 기록 내역 카드 디자인. 앱 전용·심사 무관·바로 검증. (최다 사용 화면)
2. **공항 정보 보강**(#37) — 승객예고·도착예정 데이터. 서버 파서 + 승인받은 API 키.
3. **튜닝 모드** — 기능을 모듈로 홈에 끌어와 자유 배치(바둑판). = "홈 여러 개 만들고 선택형"의 완성형. 큰 작업 → 여러 슬라이스. **(진행 중 1단계: '홈 스타일 프리셋 심플/기본/정보형' 선택 = 골라 쓰는 홈 v1 완료·검증)**
4. **지출·운행 시각 통합** — 기록 내역에서 지출과 운행을 한 타임라인에.
> 홈 선택형: 프리셋(v1, 완료) → 개별 온/오프(완료) → 카드 순서 드래그(튜닝 모드, 후속). 전부 온/오프 기본 원칙(8-8) 준수.
> 모든 항목은 착수 전 정관 3장 게이트(특허·FTO) 재확인. 배터리·안전·"구라 없게" 준수.
