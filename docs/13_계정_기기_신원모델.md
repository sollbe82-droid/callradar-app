# 콜레이더 — 계정·기기 신원 모델 (멀티폰)
*작성 2026-07-23 · 신원/계정 축 · 특허 발명2(다중소스 통합·복수 단말) 정면 · 설계헌장 통과*

> 문제(테스터 증가로 표면화): 폰 하나당 게스트 로그인이 새 계정을 만들어, 2폰·3폰 기사의 수입이 여러 계정으로 쪼개짐.
> 원칙: **계정 = 사람(하나), 기기 = 계정에 링크된 여럿.** 몇 폰을 쓰든 원장 하나로 합산.

---

## 1. 진단 (실제 코드)
- **카카오 로그인은 이미 사람 단위.** `ON CONFLICT (kakao_id)` → 같은 카카오면 어느 폰이든 같은 user_id.
- **범인 = 게스트(기기) 로그인.** `device_id` 유니크로 폰마다 새 user 생성 → 보조폰이 게스트로 시작하면 계정 쪼개짐.

## 2. 해결 (3부)
1. **페어링(신규 폰 링크):** 주폰(로그인됨)이 코드 발급(5분 만료) → 서브폰이 입력 → **로그인 없이** 같은 계정에 붙음. 카카오/구글 있으면 그냥 로그인해도 자동 병합.
2. **기기별 플랫폼:** 폰마다 사용 플랫폼(카카오/우버/티머니)을 **1~다중** 값으로 설정. 기기=플랫폼을 알면 자동감지·합산이 깔끔. 잠그지 않고 "값(리스트)"이라 변경 가능.
3. **계정 병합(기존 청소):** 이미 쪼개진 테스터 계정을 주계정으로 통합 — 운행 합집합, 설정은 주계정 유지.

## 3. 데이터 모델 (비파괴·추가형 — 심사 안전)
```
user_devices(id, user_id, device_id UNIQUE, label, platforms 'kakao,uber', linked_at)
pair_codes(code PK, user_id, expires_at, used, created_at)
users.merged_into  -- 병합된 보조계정 표시(소프트 은퇴)
```
- trips.user_id는 이미 '사람'을 가리킴 → 모든 폰이 같은 user_id로 해석되면 자동 합산(발명2).

## 4. 서버 API (구현 완료 · index.js v18)
- `POST /api/devices/register {user_id, device_id, label, platforms[]}` — 기기 등록/플랫폼 설정(upsert)
- `GET  /api/devices/:user_id` — 계정의 기기 목록
- `POST /api/pair/create {user_id}` → `{code, expires_at, ttl_sec:300}` (주폰)
- `POST /api/pair/claim {device_id, code, label?, platforms?}` → `{user_id, nickname}` (서브폰, 로그인 불필요)
- `POST /api/users/merge {primary_user_id, secondary_user_id}` — 운행 합집합, 유니크(daily_settlement·driver_settings·guild_members) 충돌은 주계정 유지
- `/api/auth/guest`에 **링크된 기기 선체크** 추가 — 페어링된 폰은 재설치해도 그 계정으로 복귀

## 5. 반박/뼈대/검증
- SMS 인증 안 씀(Play 자동리젝) → 카카오/구글/페어링코드로만.
- 투폰 중복? 보통 2~3폰=다른 플랫폼=중복 아님(자연 합집합). 같은 운행 2번일 때만 client_uuid+시각·위치 dedup(발명2·docs02) → **client_uuid(경로C 멱등) 앞당길 이유**.
- 프라이버시(07): 여러 기기 데이터 통합 동의 한 줄.
- 검증: ▸새 폰이 새 계정 안 만들고 링크? ▸병합 후 원장 하나·중복 없음? ▸계정 1:기기 N 합산? ▸Play 테스터(구글계정)≠앱 계정(사람) 구분? ▸SMS 미사용?

## 6. 남은 것 (앱 UI)
- 서브폰: 게스트 대신 "기존 계정에 연결(코드 입력)" 옵션.
- 주폰: "다른 폰 연결" → 코드 표시.
- 기기 플랫폼 다중선택 설정(더보기).
- "계정 합치기" 버튼(쪼개진 테스터용).
- 앱 로그인/온보딩 흐름에 위 API 연결.
