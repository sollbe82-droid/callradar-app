# 콜레이더 — 화면 등록소 v2 (튜닝모드) 설계
*작성 2026-07-23 · 정본 구멍(진단 09-G1) 메움 · "유저가 필요한 카드만 꾸며서 쓴다"의 뼈대 · 설계헌장 통과*

> 한 줄: 홈·탭이 고정 레이아웃이 아니라, **카드를 켜고/끄고/순서 바꾸는** 유저 대시보드.
> 이게 있어야 유저 아이디어(docs/08)가 "카드 한 줄"로 흡수되고, 앱이 커져도 조잡해지지 않는다(원칙6).

---

## 1. 최적안 — 카드 등록소 + 3규격·한 톤
- 화면은 **카드들의 나열**. 각 카드는 등록소에 **한 줄 스펙**으로 등록된다.
- **규격은 3개뿐:** `hero`(큰 강조), `tile`(작은 타일), `list`(리스트 행). → 위치·표시는 유저가 바꿔도 **틀(규격·톤·인터랙션)은 시스템이 고정** → 안 조잡해짐.
- 유저는 **켜기/끄기 + 순서**만 바꾼다(자유 색·자유 크기 아님). "내 화면을 내가 튜닝하되 규격은 지킴."

## 2. 데이터 모델
```js
Card = {
  id,                 // 'today_income'
  title, help,        // 표시명 + 도움말
  surface,            // 'home' | 'records' | 'more' ...
  size,               // 'hero' | 'tile' | 'list'  (3규격만)
  minRole,            // null | 'corp' | 'private'  (유형별 자동 노출/숨김)
  defaultVisible,     // 기본 켜짐 여부 (넣되 조용히)
}
UserLayout = {        // 유저별 배치 (Step3에서 서버 저장)
  userId, surface,
  order: [cardId...], // 순서
  hidden: [cardId...],// 끈 카드
}
```

## 3. 카드 등록소 (초기 카드 예시 — 한 줄씩 추가)
| id | 규격 | minRole | 기본 |
|----|------|---------|------|
| today_income 오늘 수입 | hero | – | ✅ |
| month_expected 이번달 예상수입 | tile | – | ✅ |
| sanap_rate 사납금 달성률 | tile | corp | ✅(법인) |
| lpg_expense LPG·경비 | tile | – | ✅ |
| airport 공항 입국예고 | tile | – | ✅ |
| hotzone 콜 핫존 | tile | – | ✅ |
| stats_summary 통계 요약 | list | – | ✅ |
| phrasecard 회화카드 | tile | – | ⬜ |
| ranking 랭킹 | tile | – | ⬜ |
| daily_close 일일마감 | tile | corp | ✅(법인) |
- **새 기능 = 여기 한 줄 추가.** 컨테이너(HomeScreen)·병합엔진·계산코어 무수정.

## 4. 흡수 규칙 (docs/08 아이디어 흡수의 착지점)
- 유저 아이디어 "화면에 뭔가 보여줘" → 등록소 **카드 한 줄**(surface·size·minRole·help).
- `defaultVisible=false`로 **넣되 조용히**(원칙5, 비대화 방지). 원하는 유저만 켬.
- `minRole`로 개인/법인 자동 분기 → if 분기 폭발 없음(driver_type 뼈대와 연결).

## 5. 구현 3단계 (쪼개기 — 로드맵 반영)
- **Step 1 (가벼움·조기 가능):** 카드 3규격 정리 + **설정에서 show/hide 토글.** → "필요한 것만"의 80%를 값싸게. (v13 마감 다듬기에 얹기 가능)
- **Step 2 (대형):** **드래그 재배치**(순서 변경).
- **Step 3 (대형):** **유저별 배치 서버 저장**(UserLayout) → 기기 바뀌어도 내 화면 유지.

## 6. 반박 / 대안 (내 안을 먼저 깜)
- **"그냥 다 보여주면 안 되나?"** — 앱이 커지면 조잡·이탈. 등록소가 절제 장치(원칙6·5).
- **"너무 큰 공사 아닌가?"** — 그래서 3단계로 쪼갬. Step1(show/hide)만으로 대부분 효용. 풀 대시보드는 자동화 사다리 안정 후(v16~17).
- **"규격을 4번째로 늘리고 싶다"** — docs/08 §3 경고신호. 3규격 사수, 안 되면 뼈대 재검토(남발 금지).
- **"필수 카드를 유저가 다 꺼버리면?"** — 최소 보호: 수입 등 핵심 카드는 "숨김 불가" 플래그 또는 "기본으로 되돌리기" 제공(원칙7 잡기).

## 7. 뼈대 연결
- **아이디어 흡수(08):** 대부분 아이디어의 착지점.
- **driver_type(04):** minRole로 유형별 카드 자동.
- **멀티소스/자가복구(02·03):** 카드는 projection을 읽어 표시(출처 배지 가능). 배치가 깨져도 데이터는 안전.
- **정체성/북극성:** "누가 써도 간편 — 필요한 것만." 정면.

## 8. 검증 체크리스트
- [ ] 새 카드가 등록소 한 줄 추가로 되나(컨테이너 무수정)?
- [ ] 3규격·한 톤이 유지되나(조잡 방지)?
- [ ] driver_type minRole로 자동 노출/숨김되나?
- [ ] defaultVisible로 비대화가 방지되나?
- [ ] (Step3) 유저 배치가 저장·복원되나?
- [ ] 핵심 카드를 다 꺼도 복구 가능한가(안전장치)?
- [ ] 규격을 억지로 4개로 늘리지 않았나?
