# 콜레이더 — 법인/개인택시 축(driver_type) 뼈대 설계
*작성 2026-07-21 · "4번째 근본 기초" · 앱 전체 동작을 가르는 축 · 여러 뼈대의 공통 기반*

> 설계헌장 통과: 최적안 + 반박/대안 + 뼈대 연결 + 검증.
> 핵심: **driverType은 '축'이지만, 코드는 driverType을 거의 안 본다.** 대신 driverType이 만들어내는 **능력 플래그·값**을 본다. 그래서 새 유형이 와도 if 분기 폭발이 없다.

---

## 1. 최적안 — 축을 코드 분기가 아니라 '값 프로파일'로 흡수
법인/개인택시는 동작이 크게 다르다:
- **법인:** 사납금 · 가스비 회사정산 · 회사 전표제출 · 예상월급 역산 · 2교대 · B2B
- **개인택시:** 사납금 없음 · 경비증빙 · 종소세 · 영수증 5년 보관 · 일자별 근무

**나쁜 방법:** 앱 곳곳에 `if (driverType === 'corp') …`. → 분기가 수십 군데로 번지고, 세 번째 유형(배달·대리 등) 오면 지옥.

**좋은 방법:** driverType은 **능력 플래그와 값 묶음(프로파일)을 고르는 스위치 하나.** 코드는 그 플래그를 본다.
```js
driver_settings.profile = {
  driverType: 'corp',        // 'corp' | 'private'  (축은 여기 하나)
  // 아래는 driverType이 정하는 '기본값'이되, 값이라 예외 허용(값으로 흡수)
  hasQuota:        true,      // 사납금 있음(corp) / 없음(private)
  fuelSettlement:  true,      // 가스비 회사정산(corp)
  submitReceipts:  true,      // 회사 전표제출(corp)
  workTimeMode:    'shift',   // 근무시간 설계와 연결 (corp=shift / private=daily)
  taxMode:         'none',    // 'none'(corp) | 'sole_proprietor'(개인택시 종소세)
  receiptArchive:  false,     // 영수증 5년 원본 보관(private=true)
}
```
- 이 값들은 **driverType에서 파생된 프리셋**이지만 저장은 값 → 회사·개인 상황별 예외 가능. (4대 뼈대 ③ "값으로 흡수")
- **코드는 `profile.hasQuota`를 보지 `driverType`을 안 본다.** → 새 유형 = 값 묶음 하나 추가, 분기 없음.

---

## 2. 축이 실제로 가르는 것들 (전부 값/플래그로)
| 영역 | 법인(corp) | 개인택시(private) | 코드가 보는 것 |
|------|-----------|------------------|----------------|
| 사납금 계산 | 함 | 안 함 | `hasQuota` |
| 가스비 | 회사정산 | 본인부담(경비) | `fuelSettlement` |
| 전표 | 회사 제출 | 경비 증빙 보관 | `submitReceipts` |
| 근무시간 | 2교대(shift) | 일자별(daily) | `workTimeMode` |
| 세무 | 없음 | 종소세 패키지 | `taxMode` |
| 영수증 | 단기 | 5년 원본 | `receiptArchive` |
| 예상월급 | 사납금 역산 | 순수입-경비 | `hasQuota` |

---

## 3. 반박 / 대안 (내가 내 안을 먼저 깐다)
- **"그냥 driverType 두 개니까 if 두 갈래면 되잖아?"** — 지금은 2개라 괜찮아 보이지만, 사납금·가스·세무·근무·전표·영수증마다 갈리면 **분기가 6군데 이상으로 번지고** 서로 얽힌다. 게다가 개인택시 안에서도 "가스비 본인부담 vs 일부회사"처럼 예외가 생긴다. 능력 플래그면 그 예외가 **값 하나 바꾸기**로 흡수된다.
- **과설계 아닌가?** — 플래그 묶음은 얇은 객체 하나일 뿐, 프레임워크가 아니다. 오히려 if 분기보다 **읽기 쉽고 테스트 쉽다**(플래그 조합만 테스트).
- **범위:** 지금은 corp/private 2개 + 위 7개 플래그면 충분. 3번째 유형은 자리만.

---

## 4. 뼈대 연결
- **화면 등록소 v2:** 카드 `minRole`이 profile을 보고 자동 노출/숨김(사납금 카드는 corp만). 축이 UI를 저절로 가른다.
- **근무시간·교대:** `workTimeMode`가 shift/daily를 결정 → 그 설계의 mode와 직결.
- **멀티소스 기록:** 소스 구성·precedence를 profile로 조정(회사 전표 vs 개인 경비).
- **계약콜 정산(⑯):** `hasQuota`/`fuelSettlement`처럼 corp 전용 기능은 profile로 노출.
- **자가복구:** taxMode='sole_proprietor'면 세무 데이터 무결성·5년 보관이 특히 중요.

---

## 5. 유형 전환(면허 변화) 안전
개인택시 면허 취득 등으로 유형이 바뀌어도:
- **데이터(기여)는 그대로 둔다.** driverType만 바꾸면 profile·계산·UI가 재구성될 뿐, 과거 운행/수입은 파생으로 다시 계산.
- 과거 기록은 그 시점 profile로 계산되도록 **기간별 profile 이력**을 남긴다(사납금 있던 시절 ↔ 없는 시절 분리).

---

## 6. 구현 순서
1. `profile` 값 객체 + driverType→프리셋 매핑(2 유형).
2. 코드의 driverType 직접 검사 제거 → **능력 플래그 참조로 교체.**
3. 등록소 `minRole`·근무시간 `workTimeMode`를 profile에 연결.
4. 유형 전환 + 기간별 profile 이력.
