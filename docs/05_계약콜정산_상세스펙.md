# 콜레이더 — ⑯ 계약콜 정산 상세 스펙
*작성 2026-07-21 · v10(4-3) · 법인 전용 수입 항목 · 멀티소스·driver_type·자가복구 통합*

> 설계헌장 통과: 최적안 + 반박/대안 + 뼈대 연결 + 검증.
> 원칙: **콜레이더가 단정하지 않고, 유저가 자기 상황대로 고른다.** (가스비 부담주체 토글과 같은 방식)

---

## 1. 무엇인가
법인이 지역콜 업체와 **월 단위 계약으로 정산**해서 기사에게 내려주는 수입.
- 실시간 운행에 안 잡힘. **한 달 뒤 덩어리**로 들어옴.
- 그래서 운행(Trip) 단위가 아니라 **월 단위 수입 항목**으로 다룬다. (가스비가 지출에 통으로 들어가듯)

---

## 2. 최적안 — 월단위 수입 항목 + 포함 토글
### 데이터 (멀티소스와 정합: 월단위 income entry)
```js
IncomeEntry = {          // Trip에 안 붙는 월단위 항목 (불변·추가형)
  id,                    // 클라 UUID (멱등)
  type: 'contract_call', // 계약콜 정산
  month: '2026-07',      // 귀속 월 (근무시간의 영업일 기준과 별개, 월 단위)
  amount: 850000,        // 월 통 금액
  includeInCompanySettlement: false, // ★ 토글 (기본 꺼짐)
  status: 'active',      // 정정은 조정항목 추가(덮어쓰기 아님)
  createdAt, deviceId,
}
```

### 토글 "회사 정산에 포함" (기본 = 꺼짐)
- **꺼짐(기본):** 개인 총수입에만 더함. 회사 매출(사납금 기준)엔 안 잡힘.
- **켜짐:** 회사 매출로도 잡혀 **사납금 계산에 반영.**

### 계산 반영
```
개인 총수입      = Σ(운행 수입) + Σ(계약콜 정산액)          // 항상
회사 매출(사납금) = Σ(운행 회사매출) + (토글 켜짐 ? 계약콜액 : 0)
예상월급         = 회사매출 기반 역산 - 사납금 - 가스비 …    // 토글이 여기 흘러들어감
```

---

## 3. 왜 토글인가 (미해결 문제를 유저에게 위임)
"계약콜 정산이 사납금에 포함되냐"는 회사·계약마다 다르고 콜레이더가 단정할 수 없다.
→ **콜레이더가 정하지 않고 토글로 유저가 자기 상황대로 고름.** 가스비 부담주체 토글과 완전히 같은 패턴 = **일관성**(조잡하지 않게, 헌장 원칙 6).

---

## 4. 반박 / 대안 (자기비판)
- **"운행마다 쪼개 넣으면 더 정확하지 않나?"** — 계약콜은 실시간에 안 잡히고 한 달 뒤 덩어리라 **운행 단위로 쪼갤 근거 데이터가 없다.** 억지로 쪼개면 가짜 정밀도. 월 통 금액이 현실과 맞다.
- **"토글이 유저에게 부담 아닌가?"** — 기본값(꺼짐)이 있어 모르면 안 건드려도 됨. 아는 사람만 켠다. 그리고 이미 가스비 토글로 익숙한 패턴이라 학습비용 0.
- **정정 처리:** 금액 틀리면 덮어쓰지 말고 **조정 IncomeEntry 추가**(자가복구 불변·추가형과 일치).

---

## 5. 뼈대 연결
- **driver_type:** 계약콜 정산은 **법인(corp) 전용.** 등록소 카드 `minRole:'corp'` → 개인택시엔 안 보임.
- **멀티소스 기록:** Trip 기여와 별개인 **월단위 IncomeEntry**로 수입 모델에 공존. 새 월단위 수입원(예: 인센티브)도 같은 틀로 한 줄 추가.
- **자가복구:** IncomeEntry도 불변·추가형 → 멱등·병합·재계산 그대로 적용.
- **화면 등록소 v2:** 수입 surface에 카드 한 줄(월 통 금액 입력 + 토글).

---

## 6. UI
- 수입 화면 카드 "계약콜 정산"(corp만).
- 월 선택 + 통 금액 입력(큰 키패드 재사용) + 토글 "회사 정산에 포함"(기본 꺼짐, 한 줄 설명: "켜면 사납금 계산에 반영돼요").
- 예상월급 화면에 토글 결과가 자연히 반영.

---

## 7. 구현 순서
1. 월단위 `IncomeEntry(type:'contract_call')` 저장(불변·추가형).
2. 개인 총수입/회사 매출 계산에 토글 분기(값 하나) 연결.
3. 수입 등록소 카드(minRole:'corp') + 입력/토글 UI.
4. 예상월급 역산에 반영 확인.

---

## 8. 검증 체크리스트

- [ ] 토글 켜면 회사 매출·사납금·예상월급에 반영되나?
- [ ] 개인택시(private)에선 이 항목이 안 보이나(minRole:'corp')?
- [ ] 금액 정정이 덮어쓰기가 아니라 조정 항목 추가로 처리되나?
- [ ] 월 통 금액이 운행 단위로 억지 분할되지 않나?
- [ ] 가스비 부담주체 토글과 같은 UX 패턴으로 일관되나?
