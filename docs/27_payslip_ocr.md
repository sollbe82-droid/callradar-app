# docs/27 — 급여명세서 사진 → OCR → 공제 자동채우기 (급여 역산 자동화)

## 목표
기사가 **급여명세서 사진 1장**을 올리면, 앱이 기본급·4대보험·조합비·기타공제를
자동으로 뽑아 **기사 설정 → 급여 공제** 칸을 채워준다. 기사는 숫자만 확인·수정 후 저장.
→ 월급명세서(홈)에 자동 반영. "매달 손입력"의 귀찮음 제거.

## 두 갈래 (기억 정리)
- **방법1 (우선/이번):** 기사가 자기 명세서를 올림 → 앱이 기사별로 역산·저장. B2C, 즉시 가치.
- **방법2 (뒤):** 회사가 입점 → 회사 표준 공제표를 올려 소속 기사 전원 일괄 적용. B2B.
  방법1을 잘 만들어 두면 방법2는 "회사 계정이 여러 기사에게 같은 값 push"로 확장.

## 왜 수동칸을 먼저 만들었나 (버리지 않음)
OCR·역산은 명세서 양식이 회사마다 달라 **100% 정확 불가**. 그래서 자동으로 채운 뒤
**반드시 사람이 확인·수정하는 화면**이 필요 → 그게 이미 만든 4칸(기본급/4대보험/조합비/기타).
사진 자동채우기는 이 칸을 대신 채워줄 뿐. 수동=1단계(완료), 사진자동=2단계(이 문서).
또한 이 항목들은 **월 고정**이라 1회 세팅(급여 인상 때만 갱신)이므로 매달 입력 아님.

## 데이터 흐름
```
[급여 공제 다이얼로그]
   └ "📷 명세서로 채우기" / "🖼 갤러리"
        → 이미지 URI
        → ML Kit KoreanTextRecognizer (온디바이스, 서버 X, 무권한 갤러리)
        → parsePayslip(text): PayParsed(base, insurance, union, other)
        → 4칸 자동 채움 + 상태문구("인식됨: 기본급 2,000,000 …")
   └ 기사가 확인·수정 → 저장 → prefs(pay_base/insurance/union/other_deduct)
        → HomeScreen 월급명세서 takeHome 반영 (이미 배선됨, v19)
```

## 파싱 규칙 (parsePayslip)
한국 급여명세서 공통 라벨을 키워드로 잡고, 라벨 뒤 첫 콤마금액을 값으로.

- **기본급**: `기본급`, `기본 급여`, `기본급여` → 뒤 금액
- **4대보험(합산)**: 아래 개별 항목을 찾으면 **합산**, 없으면 `4대보험` 총액 라벨 매칭
  - 국민연금, 건강보험, 장기요양(보험), 고용보험
- **조합비**: `조합비`, `노조비`, `노동조합비`
- **기타공제**: `소득세`+`지방소득세`(+`기타`) 합산 → 기타공제로. (세금도 실수령 차감이므로 묶음)
  - 단, 4대보험/조합비로 이미 잡은 금액은 제외.

### 매칭 세부
- OCR 텍스트는 줄바꿈이 섞임. 라벨과 값이 **같은 줄** 또는 **다음 토큰**에 올 수 있음.
- 1차: 라벨이 포함된 **줄 안**의 콤마금액.
- 2차: 없으면 라벨 위치 이후 **읽기순 첫 콤마금액**.
- 금액 정규식: `[0-9]{1,3}(?:,[0-9]{3})+` (콤마 필수 → 4대보험료 같은 큰 수 오탐 방지),
  범위 1,000 ~ 99,999,999.
- 표 컬럼(지급/공제 좌우 배치)로 값이 라벨과 멀어질 수 있음 → 완벽 X, **확인화면 전제**.

## UI (급여 공제 다이얼로그 상단에 추가)
```
[📷 명세서로 채우기]  [🖼 갤러리]      ← 신규
상태: "인식됨 — 숫자를 확인·수정 후 저장하세요"  (초록/빨강)
기본급   [ 2,000,000 ]  +
4대보험  [   180,000 ]  −
조합비   [    30,000 ]  −
기타공제 [    45,000 ]  −
[취소] [저장]
```
- OCR 실패 시: "자동 인식이 안 됐어요. 직접 입력해 주세요." + 4칸은 그대로 수동.
- 원문 보기(개발자 확인용) 토글 유지.

## 검증 (서브폰)
1. 실제/샘플 명세서 이미지로 자동채움 → 4칸 값 확인.
2. 저장 → 홈 월급명세서에 기본급 + / 4대보험·조합비·기타 − 반영·실수령 일치.
3. 인식 실패 케이스 → 수동 입력 폴백 정상.

## 실급여 0 처리 (v19 확정 — 체크박스 방식)
문제: 사납금 낮고 가스 기사부담인 도급 기사는 명세서 기본급이 **명목상**이고
통장 실지급(차인지급액)이 0에 가까움. 기본급을 그대로 더하면 홈 실수령 과대계상.

결정(옵션3-lite): 급여 공제 다이얼로그에 **"실급여 0 (기본급이 명목상)" 체크박스**(prefs `pay_zero_net`).
- 체크 ON  → 명세서는 홈 실수령에 **0 기여**(기본급 안 더함, 공제 안 뺌). 홈엔 "회사 월급(명목) 실지급 0" 안내 한 줄. → 도급 초과수익만 반영.
- 체크 OFF → 기존대로 기본급 + / 4대보험·조합비·기타 − 각 줄 합산(전액관리·월급제).

검증(서브폰): 기본급 200만·4대보험 18만·조합비 3만 입력 상태에서
- OFF: 실수령 14,954,587
- ON:  실수령 13,164,587 (−1,790,000 = 기본급−공제 제외) ✓
좌표 기반 OCR: 같은 명세서에서 기본급 2,000,000·4대보험 188,000·조합비 30,000·기타 45,980 정확 인식 ✓

향후: 회사 유형(도급/전액관리) 토글로 자동 판별(방법2 B2B) — 지금은 체크박스로 충분.
