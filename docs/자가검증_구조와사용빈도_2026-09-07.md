## ★ 먼저 — 이 데이터로 판단하면 안 되는 것

계측 시작일이 화면마다 다르다. **직접 비교하면 틀린 결론이 나온다.**

```
탭 화면 (home·radar·records·more·airport·floating)   2026-07-28 부터  → 약 40일
액티비티 14개 (insights·namecard·tax·payslip·knowhow…)  2026-09-03 부터  → 4일
```

v103 커밋 메시지에 내가 직접 적어 뒀다 —
*"insights had zero rows for 60 days — **not unused, unmeasured**"*

**따라서 액티비티의 낮은 숫자로 "안 쓰는 기능"이라고 결론 내릴 수 없다.**
특히 `payslip`(월 1회) · `tax`(연 1회)는 4일 창으로는 판단 자체가 불가능하다.

## 2. 리팩터링이 필요한가 — 자가검증 결론

### 결론: **전면 리팩터링은 근거가 없다. 두 곳만 고친다.**

판단 근거를 순서대로 적는다.

**① 실사용이 좁게 집중돼 있다.**
전체 이벤트 30,021건 중 home·records·radar·floating 이 24,870건 = **83%**.
이 화면들은 지금 돌고 있고, 기사 제보도 여기서 나온다.
구조가 나빠서 기사가 못 쓰는 화면은 없다.

**② 구조 문제로 기사가 실제로 겪는 피해는 하나로 좁혀진다.**
홈모드/간편모드가 오늘매출·근무상태를 각각 따로 불러서 **값이 어긋날 수 있다**(실측 확인).
나머지 11개 API 는 홈모드 전용이라 합칠 대상이 아니다.

**③ 복잡한 코드는 설계 실패가 아니라 현장 대응의 흔적이다.**
자정 넘김 귀속 · 일시정지 배지 · 투폰 pull 이 로컬을 덮던 것 · 새 영업일 3분치 0원 —
전부 주석에 이유가 박제돼 있다. 재작성하면 그 지식이 날아가고 같은 버그를 다시 겪는다.

**④ 실사용 200명대 서비스다.** 큰 수술 중에 매출이 틀리면 그날 기사 하루가 날아간다.

### 하기로 한 것 (합의 완료)
```
DataRepository
   ├─ 오늘매출   day_start 동기화 · 401 자가치유 · 캐시 스냅샷
   └─ 근무상태   로컬 · 서버 · 서비스 3중 충돌 정리
```

## 3. 불필요한 항목 — 확실한 것부터

### A. 죽은 서버 엔드포인트 (코드로 증명됨 · 즉시 정리 가능)

앱 코드 전체에 **경로 문자열 자체가 없는** 것들이다. 오탐 없이 확정할 수 있다.

| 엔드포인트 | 왜 죽었나 |
|---|---|
| `POST /api/auth/register` | 정관: "로그인 = 카카오 + 게스트만. 아이디/비번 폐기" |
| `POST /api/users/merge` | 계정 병합. 앱에 진입점 없음 |
| `GET /api/address` | 주소 조회. 앱은 카카오 SDK 직접 사용 |
| `POST /api/call-logs` | 콜 로그 수집. 앱에서 호출 안 함 |
| `POST /api/trips/gilbang-fare` | 길빵 요금 별도 저장. 지금은 일반 트립으로 들어감 |
| `GET /api/stats/monthly/:user_id` | 앱은 `/api/stats/daily` 로 월별을 만든다 |
| `GET /api/payslip/latest` | 앱이 다른 경로 사용 |
| `GET /api/rules`, `GET /api/tax/config` | 설정 조회. 앱에 호출부 없음 |

**★ 지우기 전에 할 일**: 이 경로들의 **실제 호출 로그**를 하루만 찍어 본다.
앱이 아닌 곳(관리자 스크립트·구버전 앱)이 부르고 있을 수 있다.
**"코드에 없다 = 아무도 안 부른다"가 아니다.**

### B. 판단 보류 — 데이터가 부족하다 (4일치)

| 화면 | 4일간 | 왜 보류인가 |
|---|---:|---|
| `payslip` | 6명 | **월 1회** 쓰는 기능. 4일로 판단 불가 |
| `tax` | 6명 | **연 1회**(부가세). 판단 불가 |
| `receipt_scan` · `receipt_reconcile` | 5·9명 | 대표가 접은 기능(AI 잔액) |
| `meter` | 3명 | 원래 부가(재미·GPS 추정) |
| `bookings` | 7명 | 승객 예약 페이지 연동 |
| `insights` | 18명 | v101 신설. 도달 문제일 가능성 |
| `namecard` · `knowhow` · `events_screen` | 14·5·8명 | 4일로는 모름 |

**최소 30일을 더 모은 뒤 다시 본다.** 지금 지우면 되돌릴 수 없다.

### C. 지우면 안 되는 것 (오해 방지)

- **`floating`** — 99명뿐이지만 **재방문 68%로 최고**. 지울 게 아니라 **더 알려야 할 기능**이다.
- **관리자·진단 엔드포인트 28개** — 앱이 안 부르는 게 정상이다.
- **`/api/events/refresh-*`, `/api/quality/*`, `/api/tolls/scan`** 등 — 운영 수동 트리거다.
