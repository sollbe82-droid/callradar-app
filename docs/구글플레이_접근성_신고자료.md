# 구글플레이 접근성 자동기록 — 제출 자료

작성 2026-08-27 · 대표 결정으로 도전 개시
근거 문서: https://support.google.com/googleplay/android-developer/answer/10964491

---

## 0. 절대 지킬 것 (틀리면 계정 해지)

1. **`isAccessibilityTool` 을 켜지 않는다.**
   구글은 "automation tools, assistants, monitoring apps" 를 접근성 도구에서 **명시적으로 제외**했다.
   콜레이더는 장애인을 위한 도구가 아니다. 허위 선언은 **개발자 계정 종료** 사유다.
2. **프로덕션에 바로 올리지 않는다. 비공개 테스트 트랙부터.**
   거부돼도 현재 유저는 무영향. 승인 확인 후에만 프로덕션으로 승격한다.
3. **선언 내용과 실제 동작이 100% 일치해야 한다.**
   "Deceptive and non-declared uses may result in suspension of your app and/or
   termination of your developer account."
4. 나중에 읽는 항목이 늘면 **선언서를 다시 제출해야 한다.**

## 1. 우리가 유리한 이유 (심사에서 설명할 논리)

| 구글이 보는 것 | 콜레이더 |
|---|---|
| 자율적으로 행동을 개시·계획·실행하는가 (2026 신설 금지) | **아니오. 읽기만 한다.** 버튼을 누르거나 대신 조작하지 않는다 |
| 읽는 범위가 좁고 명확한가 | 택시 기사앱 **4개만** 하드코딩. 다른 앱은 기술적으로 읽을 수 없다 |
| 화면을 캡처·저장하는가 | 아니오 |
| 제3자 개인정보를 수집하는가 | 아니오. 승객 이름·전화번호를 저장하지 않는다 |
| 앱 내 명시적 고지·동의가 있는가 | 있다 (`AutoRecordConsentActivity`) |
| 거부해도 앱을 쓸 수 있는가 | 쓸 수 있다. 자동기록만 꺼진 채로 둔다 |

**한 줄 요약**: 기사 본인이 자기 운행일지를 자동으로 쓰기 위해, 자기 화면에 이미 떠 있는
숫자를 읽어 기록하는 것. 대신 조작하지 않는다.

## 2. Play Console 선언서 답안

### Q1. 접근성 서비스 API가 왜 필요한가 (해당 항목 모두 선택)

- ☑ **App functionality**
- ☐ Analytics · Developer communications · Fraud prevention · Advertising · Personalization · Account management

### Q2. 접근성 기능으로 개인정보·민감정보를 수집/공유하는가

- ☑ **Yes**

> 요금 금액을 읽으므로 '수집'에 해당한다. 아니라고 하면 허위 선언이 된다.

### Q3. 어떤 데이터를 수집/공유하는가

- ☑ **Financial info → Other financial info** (운행 요금·통행료 — 기사 본인의 수입 기록)
- ☑ **App activity → Other actions** (운행 시작·손님 탑승·운행 완료 신호, 플랫폼 이름, 발생 시각)

**선택하지 말 것**
- ☐ Location — 위치는 **단말기 GPS**에서 받는다. 접근성으로 읽지 않는다. (v53에서 화면 주소 파싱 제거됨)
- ☐ Personal info / Messages / Contacts / Photos — 읽지 않는다

### Q4. 영상 링크

→ 아래 3장 참조

### 자유서술이 필요할 때 쓸 문장 (영문)

```
CallRadar is a driving log app for taxi drivers in South Korea. Korean ride-hailing
platforms (Kakao T, Uber, TmoneyGO) provide no API and send no completion
notifications, so a driver must otherwise write down every trip by hand while
working.

The accessibility service reads only text that is already displayed on the
driver's own screen in four hard-coded taxi driver apps, and only the values
needed for the driver's own log: the fare, the toll, the on-screen phrase that
indicates trip start / passenger boarded / trip completed, the platform name,
and the time those appeared.

The service never performs any action on the user's behalf. It does not tap,
navigate, or make decisions. It does not take screenshots. It reads no other app.
Origin and destination come from the device GPS, not from the screen.

Users see a dedicated in-app disclosure screen before the feature can be enabled,
must tick a checkbox and press a confirm button, and can decline and keep using
every other part of the app.
```

## 3. 영상 촬영 순서 (대표 촬영 — 이 순서 그대로)

> ⚠️ 이전에 찍어두신 "콜 잡고 운행하는 장면"은 **마지막 5번 하나**에 해당한다.
> 접근성 도구가 **아닌** 앱에 구글이 요구하는 영상은 *기능 시연*이 아니라 **고지·동의 흐름**이다.
> 아래 1~5를 **끊지 말고 한 번에** 찍는 게 좋다.

1. **앱 아이콘을 눌러 콜레이더를 여는 장면**부터 시작
2. **고지 화면까지 가는 경로를 그대로** — 어디를 눌러 자동기록 설정으로 들어가는지
3. **고지 전문이 다 보이게** — 길어서 스크롤이 필요하면 **천천히** 내린다
   (1~7번 항목이 전부 화면에 나와야 한다: 무엇을 하는지 / 어떤 앱을 읽는지 / 무엇을 읽고 저장하는지 /
   하지 않는 것 / 어떻게 쓰는지 / 누구와 공유하는지 / 끄는 방법)
4. **동의 흐름과 거부 흐름을 둘 다**
   - 체크박스 체크 → `동의하고 자동 기록 켜기` → 안드로이드 접근성 설정에서 권한 켜는 것까지
   - 그리고 **거부**했을 때 어떻게 되는지 (`사용하지 않기`), 그 뒤 **다시 고지화면을 띄우는 방법**
5. **실제로 자동기록되는 장면** ← 찍어두신 것
   - 콜 수락 → 손님 탑승 → 운행 완료 → 콜레이더 기록에 자동으로 들어간 것 보여주기
   - 화면만 봐서 이해가 안 되면 **자막이나 음성 설명**을 넣으라고 구글이 명시했다

**팁**: 4번 거부 흐름을 빼먹기 쉽다. 구글이 요구 목록에 명시한 항목이다.

## 4. 앱 쪽 준비 (개발 — 클로드가 함)

- [ ] `app/src/play/AndroidManifest.xml` 신설 — 접근성 서비스 선언 추가
      (지금은 `app/src/onestore/` 에만 있다. play 는 0개)
- [ ] `accessibility_service_config.xml` 을 play 에도 (packageNames 4개 동일)
- [ ] `isAccessibilityTool` 속성은 **넣지 않는다**
- [ ] 자동기록 진입 시 `AutoRecordConsentActivity` 가 반드시 먼저 뜨는지 재확인
- [ ] Data safety 폼도 Q3 와 같은 항목으로 맞추기 (선언서와 어긋나면 반려)
- [ ] 스토어 설명란에 자동기록 문단 추가 (아래 5번)

> **★ play 릴리스 빌드 전 필수 확인**: 매니페스트에 접근성이 들어간 빌드는
> **프로덕션에 올리지 않는다.** 비공개 테스트 트랙 전용.

## 5. 스토어 설명란에 넣을 문단

```
[자동 기록 — 선택 기능]
운행할 때마다 손으로 적지 않도록, 택시 호출 앱 화면에 이미 표시된 운행 정보를 읽어
운행일지를 자동으로 작성합니다. 안드로이드 접근성 서비스를 사용하며, 켜기 전에 무엇을
읽고 무엇을 저장하는지 앱 안에서 자세히 알려드리고 동의를 받습니다.

· 읽는 앱: 카카오 T 드라이버, 우버 드라이버, 티머니GO, 티머니GO 내비 (이 4개만)
· 읽는 값: 요금, 통행료, 운행 시작·탑승·완료를 알리는 화면 문구, 플랫폼 이름, 시각
· 화면을 캡처하거나 저장하지 않습니다
· 회원님을 대신해 앱을 조작하지 않습니다 (읽기만 합니다)
· 동의하지 않아도 다른 기능은 그대로 사용할 수 있고, 언제든 끌 수 있습니다
```

## 6. 제출 순서

1. 앱 준비 (4번) 완료 → **비공개 테스트 트랙**용 AAB 빌드
2. Play Console → 앱 콘텐츠 → **접근성 서비스 선언** 작성 (2번 답안)
3. Play Console → 앱 콘텐츠 → **데이터 세이프티** 항목을 Q3 와 일치시킴
4. 영상 업로드 (유튜브 비공개 링크 등) → 선언서에 링크 첨부
5. 비공개 테스트 트랙에 업로드 → 검토 대기
6. **승인 확인 후에만** 프로덕션 승격 (그때 대표 확인 1회)

## 7. 거부되면

거부 사유가 오면 그 문구를 그대로 가져오시라. 사유별로 다르다:

- **"접근성 도구가 아니다"** → 우리는 애초에 그렇게 선언 안 했으니 재설명하면 된다
- **"고지가 불충분하다"** → 고지 화면 문구·위치를 고친다
- **"자율 행동으로 보인다"** → 읽기 전용임을 코드 근거로 설명 (버튼 클릭 API 미사용)
- **정책 위반 통보** → 즉시 트랙 내리고, 원스토어 전용으로 되돌린다 (현재 유저는 무영향)
